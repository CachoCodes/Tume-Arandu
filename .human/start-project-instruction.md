# Первый запуск в новом проекте

1. Открой проект в своём агенте и попроси прочитать AGENTS.md.
2. Определи назначение продукта, пользователей и первый нужный сценарий. Если это уже описано в запросе/документах, повторно не спрашивай.
3. Заполни `specs/common/main.md` только подтверждёнными фактами. Техническую карту заполняй по реальным путям, а не шаблонным предположениям.
4. Для первой отслеживаемой работы создай WI с outcome, in/out и наблюдаемыми AC; назначь owner и статус в BOARD.
5. По образцам `specs/examples/` создай только необходимые спецификации. Назначь свободные ID, опиши сценарии и ошибки, зарегистрируй в SPEC-MAP. Draft становится active перед зависимой реализацией после снятия существенной неопределённости.
6. Реализуй тот же атомарный результат, добавь @spec на точки ответственности и прямые contract tests, выполни соответствующие проверки и spec-lint.
7. При Done запиши evidence и архивируй WI. Если работа прервалась — оставь короткий checkpoint с Next.

Не создавай инфраструктуру, отдельную дизайн-систему, все типы спецификаций или ROADMAP без необходимости. Если нужна стратегическая карта, используй `specs/examples/ROADMAP.md`.
Не меняй стек или требования окружения проекта ради установки workflow.
