## Цель

Перенести в приложение **концепты уроков** из утверждённого браузерного прототипа и добавить для них отдельные узлы-книжечки на карту. Концепт — это объяснение темы перед заданиями: вертикальная лента смысловых блоков, которая раскрывается по кнопке «Продолжить», с короткими встроенными проверками. Задания прототипа (вкладка «Типы заданий») в этот перенос **не входят**.

Порядок прохождения каждой основной темы с концептом: **книжечка → основной урок с прежним номером → 2–3 отдельных повторения → книжечка следующей темы**. Для первых трёх тем карта начинается именно с книжечки перед уроком 1. Книжечка открывает концепт, номерной узел открывает упражнения того же урока; повторения остаются отдельными уроками. Не превращай книжечку в повторение и не заменяй ею номерной узел.

## Источник

Три концепта: «Прямоугольный треугольник» (8 блоков), «Треугольники в жизни» (6), «Измерение с треугольником» (6). Содержание лежит в массиве `concepts` в `<script>`, рисунки строят функции `triangleSvg`, `compareArt`, `rampArt` и `art`.
- Тексты прототипа на русском только для проверки обучения. В курсе они должны быть на Guaraní (`gn-PY`) и испанском (`es`), как весь JSON курса (см. `spec://modules/learning/FEAT-010-learning-demo#lesson-content`). Перевод Guaraní помечай как черновик для проверки носителем.
- Visual-эталон: цвета и компоненты уже взяты из `ui/CourseApp.kt` (`ScreenHeader`, `ExercisePanel`, `ChoiceContent`, `PrimaryAction`, `HelpActionButton`, плашка результата). Используй эти компоненты, а не новые копии.

## Что сейчас в коде

- `course/Course.kt`: `Lesson.theory: List<TheoryBlock(type, body)>`. `CourseLoader` принимает `type` из `text`, `formula`, `example`. Теория загружается, но **не показывается** ни на одном экране.
- Урок сразу открывает `ExercisePanel`. Концептов в приложении нет. `CourseMap3D.kt` строит номерные узлы и повторения, сопоставляет их с уроками по порядку и открывает через общий `onOpen(lesson)`; отдельного узла концепта пока нет.
- Формат курса: `spec://modules/learning/PROP-011-course-json-format`. Новые виды визуала появляются только через `#new-visuals`: прототип → согласование владельцем → запись в канон. Согласование владельца на этот вид концептов получено; зафиксируй его в WI.

## Что сделать

1. **Канон.** В PROP-011 опиши формат концепта. Предложение: у урока появляется необязательный `concept: { blocks: [...] }`. Блок содержит `id`, локализованные `title` и `text`, `visual` из закрытого списка и необязательный `check`. `check` устроен как `multiple_choice`: `options[{id,text}]`, `correctOptionId`, локализованные `good` и `bad`; для выбора касанием фигуры добавь `mode: "figure"`. Закрытый список `visual` для концептов: `triangle_vertices`, `right_angle`, `compare_figures`, `catheti`, `hypotenuse`, `rotated_180`, `labeled_sides`, `ramp`, `ramp_right`, `ramp_hypotenuse`, `known_sides`, `unknown_side`, `other_numbers`. В FEAT-010 `#course-map`, `#flow` и `#lesson-content` опиши отдельную книжечку перед основным уроком, её открытие и переход к упражнениям. Старый `theory` не ломай: урок без `concept` работает как сейчас.
2. **Карта.** Для каждого основного урока с `concept` добавь непосредственно перед его номерным узлом отдельную платформу-книжечку. Она чуть меньше основного урока, но заметно больше повторения: при текущих радиусах карты 30 для урока и 21 для повторения используй ориентир 27 для книжечки. Нарисуй узнаваемую открытую книгу средствами существующего Canvas; у книжечки нет номера урока. Номера основных уроков остаются 1, 2, 3; после каждого по-прежнему идут его повторения. Расставь новые узлы и дорожку без наложения на платформы, декор и панели, сохрани вертикальные этапы и их прокрутку. Книжечка относится к тому же стабильному ID урока, но является отдельным типом узла, а не новым уроком в JSON: не сдвигай сопоставление существующих уроков/повторений с узлами и не меняй их ID.

   Первая доступная точка — книжечка урока 1. Завершение концепта открывает номерной урок 1, завершение его упражнений открывает первое повторение; далее действует обычный порядок. Книжечка урока 2 появляется после повторений урока 1, аналогично для урока 3. Уже завершённые уроки и повторения не блокируй задним числом: для них соответствующая книжечка считается доступной и пройденной на карте, даже если отдельного сохранённого флага концепта ещё нет. При повторном нажатии на книжечку можно перечитать концепт; нажатие на номерной урок открывает его упражнения. Для уроков без `concept` книжечку не создавай. Добавь доступные TalkBack-описания и состояния для книги, урока и повторения.
3. **Данные.** Добавь блоки трёх концептов в `app/src/main/assets/courses/trigonometry.json` к урокам `right-triangle` и `triangle-in-life`, а третий к уроку по измерению сторон (найди его по теме; если его нет, спроси владельца, не выдумывай). Обнови `CourseLoader` и валидацию: неизвестный `visual`, пустые тексты и `correctOptionId` без соответствующего варианта должны давать понятную ошибку загрузки.
4. **Экран концепта** в Compose, по образцу прототипа:
   - Шапка `ScreenHeader` и узкая шкала прогресса по центру: доля раскрытых блоков.
   - Лента: каждый блок — заголовок, текст, рисунок. Без карточек и рамок, блоки разделены тонкой линией. Следующий блок появляется **ниже** предыдущих, лента плавно прокручивается к нему, прежние блоки остаются доступны прокруткой вверх.
   - Нижняя панель как в `ExercisePanel`: слева **робот-тьютор** (отдельный промпт `docs/handoff/prompt-tutor-robot.md`; если он ещё не сделан, оставь место под кнопку 52 dp), справа `PrimaryAction`. Подписи кнопки: «Продолжить», «Проверить ответ», «Исправить ответ», на последнем блоке «К заданиям».
   - Встроенная проверка: варианты стилем `ChoiceContent` в нижней панели, а для `mode: "figure"` выбор касанием самой фигуры в ленте. Результат показывается нижней панелью, **целиком** залитой зелёным `#E9F7EE` или розовым `#FFEDE8`: иконка ✓ или ↻, текст `good` или `bad`, кнопка «Показать решение». После неверного ответа «Исправить ответ» возвращает к выбору. Пока проверка не пройдена, «Продолжить» недоступно.
   - Рисунки рисуй на `Canvas` так же, как `TriangleContextDiagram`: синие стороны `Accent`, толщина 4 dp, оранжевая отметка 90° `#EEA44B`, выделенная сторона оранжевая, подписи жирные цвета `Ink`. Геометрию и подписи бери из SVG прототипа (координаты там в `viewBox 320×205`).
   - После последнего блока действие «К заданиям» завершает книжечку и открывает упражнения связанного номерного урока. При повторном входе в пройденную книжечку ученик может пролистать её или сразу перейти к заданиям.
5. **Прогресс.** Храни только номер последнего раскрытого блока и факт прохождения концепта, через существующий `progress`-репозиторий, по ID связанного урока. Концепт не начисляет XP и не меняет mastery. Завершённый ранее урок считается достаточным для доступа к его упражнениям и следующим узлам независимо от нового флага концепта. Существующий прогресс пользователя не очищай и не мигрируй с потерями.
6. **Доступность.** У каждого рисунка есть `contentDescription`. Фигуры в `mode: "figure"` имеют роль переключателя и работают с TalkBack. Крупные области нажатия, не меньше 48 dp.

## Чего не делать

- Не переносить задания из вкладки «Типы заданий» прототипа.
- Не переписывать соседние экраны заданий ради концептов.
- Не рисовать HTML внутри приложения и не встраивать WebView.
- Не добавлять зависимости без необходимости.
- Не запускать концепт автоматически при нажатии на номерной урок: вход в него — через книжечку на карте.
