# WAL-PROTOCOL

WAL — память незавершённой работы. Создавай checkpoint при паузе до Done, передаче, переключении задачи, блокере или значимом деструктивном шаге. При обычном старте и после завершения запись не нужна.

Один активный WI имеет не больше одного checkpoint:

```md
### WI-011: Приглашение участника (@handle)
- Work: [WI-011](work/WI-011-invite.md)
- Updated: YYYY-MM-DD
- Checkpoint: API и успешный сценарий проверены.
- Next: проверить повторное приглашение и состояние ошибки в UI.
- Blocker: —
```

Обязательны Work, Updated, Checkpoint, Next, Blocker. Не копируй scope, acceptance и историю команд из WI.
Статус/owner живут в BOARD. Blocker должен согласовываться с BOARD.
Редактируй только свои checkpoints. Cross-work и Decisions Pending содержат только актуальные зависимости/решения; принятое решение переноси в spec/WI.
При возобновлении прочитай WI, строку BOARD и checkpoint; проверь актуальность следующего шага.
При Done перенеси результат/evidence в WI, удали checkpoint. Завершённая история живёт в архиве WI и Git.
Legacy Completed можно сохранить до миграции; новых записей туда не добавляй.
