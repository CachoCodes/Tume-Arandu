# PROP-011: Единый JSON-пакет уроков {#root}

## Простыми словами {#plain-language}

Автор добавляет урок в один JSON-файл курса. Тот же формат задаёт текст на Guaraní и Español, ответы, объяснения и разрешённый визуальный вариант задания. Android проверяет содержимое до показа и рисует новый согласованный экран по данным, без правил для специальных ID. Так можно добавлять уроки через pull request, не меняя Compose для каждого упражнения.

## Scope {#scope}

- In: формат встроенного курса v2, обязательные поля, локализация, валидатор, явные варианты оформления и правила изменения ID.
- Out: экран выбора пользовательского файла, исполняемый контент, удалённый каталог, AI-генерация и проверка математической истинности текста.

## Пакет и локализация {#package}

Один UTF-8 JSON под `app/src/main/assets/courses/trigonometry.json` содержит `schemaVersion: 2`, стабильный `id`, положительный `revision`, `defaultLocale: "gn-PY"`, локализованный `title` и массив `lessons` из 1–26 учебных записей (предел текущей карты курса). Испанская версия находится в том же файле в ключе `es`; отдельный JSON локализации не используется. Все видимые авторские строки — объекты `{"gn-PY": "...", "es": "..."}`. Оба значения обязательны, непусты и выбираются по языку экрана. ID, ключи правильных ответов и порядок упражнений общие для языков.

Урок: `id`, `source`, `title`, `objective`, `theory[{type,body}]`, `xpReward` и непустой `exercises[]`. Допустимые `theory.type`: `text`, `formula`, `example`. Упражнение: `id`, `type`, `visual`, `prompt`, `hint`, `solutionSteps[]` и поля типа. `hint` и каждый шаг решения локализованы; решение непусто. Формулировка содержит только вопрос/задание: повторный подзаголовок и счётчик шагов на экране не выводятся.

## Концепт перед заданиями {#concept}

Урок может содержать `concept: {blocks:[...]}` с непустым списком. Каждый блок имеет уникальный в рамках концепта `id`, локализованные непустые `title` и `text`, а также `visual` из закрытого списка: `triangle_vertices`, `right_angle`, `compare_figures`, `catheti`, `hypotenuse`, `rotated_180`, `labeled_sides`, `ramp`, `ramp_right`, `ramp_hypotenuse`, `known_sides`, `unknown_side`, `other_numbers`, `angle_arc`, `similar_triangles`, `sine_ratio`, `cosine_ratio`, `tangent_ratio`, `ratio_choice`, `tree_shadow`. Необязательный `check` содержит `options[{id,text}]` (минимум два уникальных ID), `correctOptionId`, локализованные `good` и `bad`, а также необязательный `mode: "figure"` для выбора касанием фигуры. Правильный ID обязан присутствовать в `options`; `mode: "figure"` разрешён только для `compare_figures`. Неизвестные виды и пустые строки отвергаются с путём до блока.

Существующие уроки без `concept` загружаются без изменений. Старый `theory` сохраняется. ID урока и заданий не меняются при добавлении концепта.

## Происхождение урока {#lesson-source}

Каждый урок в JSON содержит `"source": {"madeWith": "Dulce Duro", "basedOn": "MEC Paraguay"}`: урок подготовлен с Dulce Duro и основан на программе по математике Ministerio de Educación y Ciencias Парагвая. Значения фиксированы; урок без `source` или с другим значением отклоняют валидатор и загрузчик. Поле служебное и на экране не показывается.

## Типы и оформление {#exercise-visuals}

Четыре типа данных порождают семь согласованных экранов. `visual` задаёт разрешённый вариант, не идентификатор урока/задания:

| type | visual | Дополнительные поля |
|---|---|---|
| `multiple_choice` | `triangle_choice`, `angle_builder`, `standard_choice` | `options[{id,text}]`, `correctOptionId` |
| `input` | `fraction_triangle`, `straight_angle`, `standard_number`, `standard_fraction` | `acceptedAnswers[]` |
| `matching` | `ratio_pairs`, `angle_pairs`, `standard_pairs` | `leftItems[]`, `rightItems[]`, `pairs[{leftId,rightId}]` |
| `step_by_step` | `radical_fraction`, `standard_steps` | `steps[{prompt,acceptedAnswers,explanation}]` |

`text`, `prompt` и `explanation` в вариантах и шагах локализованы; `acceptedAnswers`, `correctOptionId` и `pairs` не локализуются. Для `angle_pairs` правые элементы получают `diagram: "acute"|"right"|"straight"`; иная диаграмма отвергается. `ratio_pairs` показывает математические имена функций и узкие вертикальные дроби; текст числителя и знаменателя кодируется в `text` одной строкой через `/`. `triangle_choice` показывает варианты в нижней зоне и дробь вертикально, `fraction_triangle` — белую увеличенную схему 3–4–5 с α и два поля дроби. `angle_builder` управляется ползунком, `straight_angle` показывает прямую линию. `radical_fraction` отображает ввод `√числитель/знаменатель` без дополнительного заголовка шага.

Геометрические задания по тригонометрии содержат `triangle: {angleDegrees, angleLabel, base, opposite, hypotenuse}`. Угол — число строго между 0 и 90; подписи — непустые математические строки. Схема показывается сверху на белом фоне, использует стороны текущей задачи, обозначает неизвестную сторону `?` и не привязывается к ID. Для 30°, 60° и 45° используются соответствующие пропорции. Выбор ответа с такой схемой располагается по центру в нижних карточках; дроби вертикальны. Абстрактное сопоставление формул и задания с лучами используют свои рисунки.

### Визуальная часть обязательна {#visual-rule}

Каждое задание, кроме сопоставления, показывает рисунок, который помогает понять вопрос: схему треугольника, лучи угла, прямую или ползунок. Экран только из текста не допускается. `standard_choice`, `standard_number`, `standard_fraction` и `standard_steps` рисуют схему из `triangle`, поэтому без `triangle` отклоняются. Подписи схемы не пересекают её линии: подпись угла стоит на биссектрисе с отступом от обеих сторон и дуги, а если острый треугольник для неё слишком узок — снаружи, слева от вершины. Сопоставление (`ratio_pairs`, `angle_pairs`, `standard_pairs`) — доска крупных карточек в два столбца без треугольника; `triangle` у него отклоняется. В каждом столбце ровно три карточки (три пары); иное число отклоняется.

### Каталог шаблонов {#templates}

`app/src/main/assets/templates/exercise-templates.json` — пакет v2, в котором ровно одно согласованное задание на каждую пару `type/visual` (ID `tpl-<visual>`). Это эталон вида: новое задание копирует шаблон нужного вида и меняет только содержание — `id`, `prompt`, `hint`, `solutionSteps`, варианты и ответы, данные `triangle` — не добавляя и не удаляя поля вида. Шаблоны проходят тот же валидатор; тест требует, чтобы каталог покрывал все разрешённые пары. Каталог и любое задание курса открываются на эмуляторе в режиме просмотра: `adb shell am start -n com.guarani.mathdemo/.MainActivity -e preview templates/exercise-templates.json [-e exercise <id>]` (для курса — `-e preview courses/trigonometry.json`). Режим просмотра открывает все уроки и пишет ответы в отдельное хранилище, которое очищается при запуске; сохранённый прогресс ученика не меняется.

### Новые виды заданий {#new-visuals}

Список `type/visual` выше — всё, что сейчас можно использовать. Формат оставляет место для новых визуальных видов заданий, но новый `visual` появляется только так: браузерный прототип в `tools/` → согласование владельцем → запись в эту таблицу и правила оформления → поддержка в `tools/validate-course.py` и `CourseLoader` → согласованный экран в Compose → проверка в APK. Пока шаги не пройдены, неизвестный `visual` отклоняется, а автор урока выбирает из существующих.

Все визуальные варианты используют согласованную светлую бело-синюю подачу, закреплённые нижние действия, крупные доступные области нажатия, контурные символы помощи/калькулятора, зелёную или красную нижнюю плашку результата. Английские подписи и копирование брендинга другой программы не допускаются.

## Проверка и совместимость {#validation}

Загрузчик принимает только v2. До создания Course он проверяет корневые поля, поддерживаемые пары `type/visual`, обе локализации, непустые и уникальные ID уроков и упражнений, уникальные ID вариантов в пределах упражнения, существование правильного варианта и полное однозначное соответствие matching, непустые `acceptedAnswers` и шаги. Путь ошибки должен указывать на урок/упражнение и поле. Неподдерживаемый тип, visual или diagram отклоняется; строки не выполняются как код, HTML или математические выражения.

Встроенный курс мигрирует в v2 без смены `id` курса, уроков и упражнений и без очистки DataStore. `revision` описывает редакцию пакета; изменение только текста не меняет ID. Новый смысл задания или иной правильный ответ требует новый exercise ID, чтобы старый прогресс не засчитывался для изменённого задания. В текущей версии приложение показывает один встроенный курс; пользовательский импорт нескольких пакетов и пространство имён прогресса для них требуют отдельной реализации.

## Добавление урока {#authoring}

Автор копирует пример в `docs/course-json-v2.md`, добавляет уникальный lesson ID и упражнения с разрешёнными `type/visual`, заполняет оба языка и решения, запускает `python3 tools/validate-course.py app/src/main/assets/courses/trigonometry.json`, затем проверяет экран в debug APK. AI-агент перед созданием или изменением урока следует `docs/lesson-authoring-ai.md`; AI-файл проходит ту же проверку, что и файл человека. Валидатор подтверждает структуру и ссылки, но математическую корректность и перевод проверяет автор/преподаватель.

## Acceptance {#acceptance}

- AC-1: оба языка загружаются из одного v2 файла с одинаковыми ID и ответами.
- AC-2: неверный или неподдерживаемый пакет отклоняется до показа курса с указанием проблемного пути.
- AC-3: новый урок с разрешёнными `type/visual` отображается согласованным экраном без проверки специальных ID в UI.
- AC-4: прежний прогресс встроенного курса читается без сброса.
- AC-5: документация автора и CLI-валидатор позволяют подготовить пакет для PR.
