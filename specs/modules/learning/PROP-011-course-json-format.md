# PROP-011: Единый JSON-пакет уроков {#root}

## Простыми словами {#plain-language}

Автор добавляет урок в один JSON-файл курса. Тот же формат задаёт текст на Guaraní и Español, ответы, объяснения и разрешённый визуальный вариант задания. Android проверяет содержимое до показа и рисует новый согласованный экран по данным, без правил для специальных ID. Так можно добавлять уроки через pull request, не меняя Compose для каждого упражнения.

## Scope {#scope}

- In: формат встроенного курса v2, обязательные поля, локализация, валидатор, явные варианты оформления и правила изменения ID.
- Out: экран выбора пользовательского файла, исполняемый контент, удалённый каталог, AI-генерация и проверка математической истинности текста.

## Пакет и локализация {#package}

Один UTF-8 JSON под `app/src/main/assets/courses/trigonometry.json` содержит `schemaVersion: 2`, стабильный `id`, положительный `revision`, `defaultLocale: "gn-PY"`, локализованный `title` и непустой массив `lessons`. Испанская версия находится в том же файле в ключе `es`; отдельный JSON локализации не используется. Все видимые авторские строки — объекты `{"gn-PY": "...", "es": "..."}`. Оба значения обязательны, непусты и выбираются по языку экрана. ID, ключи правильных ответов и порядок упражнений общие для языков.

Урок: `id`, `title`, `objective`, `theory[{type,body}]`, `xpReward` и непустой `exercises[]`. Допустимые `theory.type`: `text`, `formula`, `example`. Упражнение: `id`, `type`, `visual`, `prompt`, `hint`, `solutionSteps[]` и поля типа. `hint` и каждый шаг решения локализованы; решение непусто. Формулировка содержит только вопрос/задание: повторный подзаголовок и счётчик шагов на экране не выводятся.

## Типы и оформление {#exercise-visuals}

Четыре типа данных порождают семь согласованных экранов. `visual` задаёт разрешённый вариант, не идентификатор урока/задания:

| type | visual | Дополнительные поля |
|---|---|---|
| `multiple_choice` | `triangle_choice`, `angle_builder`, `standard_choice` | `options[{id,text}]`, `correctOptionId` |
| `input` | `fraction_triangle`, `straight_angle`, `standard_number`, `standard_fraction` | `acceptedAnswers[]` |
| `matching` | `ratio_pairs`, `angle_pairs`, `standard_pairs` | `leftItems[]`, `rightItems[]`, `pairs[{leftId,rightId}]` |
| `step_by_step` | `radical_fraction`, `standard_steps` | `steps[{prompt,acceptedAnswers,explanation}]` |

`text`, `prompt` и `explanation` в вариантах и шагах локализованы; `acceptedAnswers`, `correctOptionId` и `pairs` не локализуются. Для `angle_pairs` правые элементы получают `diagram: "acute"|"right"|"straight"`; иная диаграмма отвергается. `ratio_pairs` показывает математические имена функций и узкие вертикальные дроби; текст числителя и знаменателя кодируется в `text` одной строкой через `/`. `triangle_choice` показывает варианты в нижней зоне и дробь вертикально, `fraction_triangle` — белую увеличенную схему 3–4–5 с α и два поля дроби. `angle_builder` управляется ползунком, `straight_angle` показывает прямую линию. `radical_fraction` отображает ввод `√числитель/знаменатель` без дополнительного заголовка шага.

Все визуальные варианты используют согласованную светлую бело-синюю подачу, закреплённые нижние действия, крупные доступные области нажатия, контурные символы помощи/калькулятора, зелёную или красную нижнюю плашку результата. Английские подписи и копирование брендинга другой программы не допускаются.

## Проверка и совместимость {#validation}

Загрузчик принимает только v2. До создания Course он проверяет корневые поля, поддерживаемые пары `type/visual`, обе локализации, непустые и уникальные ID уроков и упражнений, уникальные ID вариантов в пределах упражнения, существование правильного варианта и полное однозначное соответствие matching, непустые `acceptedAnswers` и шаги. Путь ошибки должен указывать на урок/упражнение и поле. Неподдерживаемый тип, visual или diagram отклоняется; строки не выполняются как код, HTML или математические выражения.

Встроенный курс мигрирует в v2 без смены `id` курса, уроков и упражнений и без очистки DataStore. `revision` описывает редакцию пакета; изменение только текста не меняет ID. Новый смысл задания или иной правильный ответ требует новый exercise ID, чтобы старый прогресс не засчитывался для изменённого задания. В текущей версии приложение показывает один встроенный курс; пользовательский импорт нескольких пакетов и пространство имён прогресса для них требуют отдельной реализации.

## Добавление урока {#authoring}

Автор копирует пример в `docs/course-json-v2.md`, добавляет уникальный lesson ID и упражнения с разрешёнными `type/visual`, заполняет оба языка и решения, запускает `python3 tools/validate-course.py app/src/main/assets/courses/trigonometry.json`, затем проверяет экран в debug APK. AI-файл проходит ту же проверку, что и файл человека. Валидатор подтверждает структуру и ссылки, но математическую корректность и перевод проверяет автор/преподаватель.

## Acceptance {#acceptance}

- AC-1: оба языка загружаются из одного v2 файла с одинаковыми ID и ответами.
- AC-2: неверный или неподдерживаемый пакет отклоняется до показа курса с указанием проблемного пути.
- AC-3: новый урок с разрешёнными `type/visual` отображается согласованным экраном без проверки специальных ID в UI.
- AC-4: прежний прогресс встроенного курса читается без сброса.
- AC-5: документация автора и CLI-валидатор позволяют подготовить пакет для PR.
