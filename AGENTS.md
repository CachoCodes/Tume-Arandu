# Spec Drive

Начни с `specs/protocols/BOOT.md` и выбери маршрут текущей задачи.
Читай только релевантные протоколы, спецификации, код и проверки.
Сохраняй существующие UI/UX возможности, если пользователь не просил их менять.
Используй окружение и команды проекта: macOS, Linux, WSL или Windows согласно его требованиям.
Не меняй стек или зависимости только ради окружения агента.
<!-- spec-drive:end -->

## Быстрый цикл визуальных правок

- Источник UI уроков и заданий — Android Compose в `app/`. `tools/local-preview.py` только показывает экран эмулятора на localhost. Не рисуй отдельную HTML-версию задания или галерею макетов, если пользователь прямо этого не попросил.
- Перед правкой назови конкретный дефект и найди существующий компонент. Меняй его минимально; не переписывай соседние типы заданий ради просмотра.
- После группы связанных правок выполни одну инкрементальную `:app:assembleDebug`, установи APK через `adb install -r` и проверь затронутый экран плюс ближайшее регрессионное состояние. Полный обход всех уроков нужен только при изменении общего компонента или курса.
- Не очищай и не подменяй сохранённый прогресс пользователя ради снимков. Для обзора используй уже открытый экран или отдельное тестовое состояние; если его нет, сообщи предел проверки.

## Новые уроки

- Перед созданием или изменением урока прочитай `docs/lesson-authoring-ai.md`: у каждого урока `source` (Dulce Duro, MEC Paraguay), у каждого задания, кроме сопоставления, визуальная часть; новое задание — копия шаблона из `app/src/main/assets/templates/exercise-templates.json` с изменённым содержанием.
